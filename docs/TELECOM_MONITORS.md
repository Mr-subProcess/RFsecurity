# RFSEC 0.6.0 Telecom Monitor APIs

These modules are defensive analyzers. Their inputs are saved observations, saved IQ8 captures, or sanitized gateway audit logs. None opens an RF transmit path, impersonates a PLMN, induces a UE attach, sends SMS/calls, or accesses subscriber secrets.

## CellAnomalyDetector

Header: `rfsec/cellular_anomaly.hpp`  
Implementation: `src/cellular_anomaly.cpp`

`CellAnomalyDetector` accepts `CellObservation` records that contain only cell/network metadata (RAT, MCC/MNC, TAC, cell identity, PCI, channel number, received signal measurements and a separately sourced ciphering status). The detector reports allowlist mismatches, rapid identity changes, potential PCI reuse collisions, very strong received-signal values and externally reported ciphering disabled. These are heuristics: normal mobility, planned PCI reuse and measurement-source bugs can produce findings. It never handles IMSI, IMEI, MSISDN, keys or traffic payloads.

CSV fields: `timestamp_ms,rat,mcc,mnc,tac,cell_id,pci,arfcn,rsrp_dbm,rsrq_db,ciphering`. `rat` is one of GSM, UMTS, LTE or NR; ciphering is one of enabled, disabled, unknown or not_reported.

## InterferenceMonitor

Header: `rfsec/interference_monitor.hpp`  
Implementation: `src/interference_monitor.cpp`

`InterferenceMonitor` processes an existing interleaved signed IQ8 file in bounded FFT windows. It calculates RMS dBFS, spectral flatness, peak-to-median-bin ratio, occupied-bin fraction and clipping fraction. Broad-band-like energy and clipping can be caused by normal emitters, gain settings, receiver overload, front-end saturation or other conditions. These metrics are not proof of malicious interference, and they do not identify an actor or intent. There is no IQ mutator for transmission and no RF TX interface.

## CommsGatewayAuditor

Header: `rfsec/comms_audit.hpp`  
Implementation: `src/comms_audit.cpp`

`CommsGatewayAuditor` processes SMSC/PBX logs that have been sanitized before ingestion. It checks non-verified origin status, untrusted route status, burst rate, unique-peer fan-out and failed events. The CSV accepts 16-64 hexadecimal characters for actor/peer tokens; tokens should be keyed HMACs generated by the log owner. The parser rejects raw phone numbers in E.164 form and message bodies are not part of the schema.

CSV fields: `timestamp_ms,event_type,direction,actor_token,peer_token,auth_status,route_status,result`. Event type is SMS or CALL; direction IN or OUT. The report is an audit of prior gateway activity, not a send or call API.

## CLI

```bash
rfsec telecom cell-audit --in cell_observations.csv --allow-plmn 286-01 --out cells.csv
rfsec telecom rf-audit --in capture.iq8 --rate 2000000 --fft-size 2048 --out rf.csv
rfsec telecom comms-audit --in gateway_events.csv --window-sec 60 --max-events 20 --max-fanout 10 --out gateway.csv
```
